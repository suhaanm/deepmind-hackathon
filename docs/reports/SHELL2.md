# SHELL2 report: hidden side panel, menu bar as control center

## What shipped
- **`showDock` setting** (`src/shared/settings.ts`, default false). An older saved profile without the key reads as false (`coerceSettings` defaults missing keys; tested).
- **Startup visibility** (`src/main/panel-rules.ts`, `shouldShowDockAtStart`): the panel starts hidden unless `showDock`, or setup is unfinished (`onboardingDone` false), or `showMenuBarIcon` is off (no menu bar item to bring it back; my addition for safety), or never when headless. `windows.ts` takes `showDockAtStart`; the dock window is always created and loaded, just not shown.
- **Menu bar = control center** (`src/main/tray.ts`): "Show panel" is now a checkbox (checked = visible, persisted as `showDock`), then Talk to Marcus/Amelia, Type instead, Mute/Unmute microphone, Stop, Run the demo walkthrough, Set up again…, Permissions…, Quit. Clicking the icon toggles the panel (it used to toggle collapsed/expanded). The Settings switch "Keep the panel open" (Settings → Basics, `SettingsPanel.tsx`) is the same setting; flipping it from either place shows or hides the window. While setup is unfinished a hide request is ignored.
- **State at a glance**: `tray.setTitle` word next to the icon, tooltip, and icon. Asleep: no word; Listening (waiting for its name); Connecting; Live; Thinking; Speaking; Muted; Working… (any agent chip running); Problem (error). Priority: error, muted, working, phase. Icons reuse the three existing template PNGs (idle, live, muted; working uses live, error uses idle plus the word). No new art was drawn.
- **Shortcut** `CommandOrControl+Alt+P` (fallback `CommandOrControl+Alt+Shift+P`) in `hotkey.ts`, registered only when `togglePanel` is passed (index.ts passes it); taken combos are tolerated (no error banner, the menu bar still works); shown on the menu checkbox when registered.
- **Type instead from hidden**: shows the panel on the chat view; when the session that follows ends, the panel goes back to hidden (unless `showDock` is on).
- **Accessibility and hardening**: (e) captions: the visible lines are `aria-hidden`; a visually hidden `role="log"` announces final lines only (`Captions.tsx`, `announcedLines`). (c) segmented controls: arrow keys were already there; targets are now 44 px (settings) and the compact chat Talk | Type pill keeps its look with a 44 px hit area via `::before`. (f) `windows.ts`: deny new windows, open plain http(s) links in the browser via `shell.openExternal`, block `will-navigate` (the guards already existed; openExternal is new); the stage window now has the same guards (navigation to local `file:` pages stays allowed). The toast window already had both.
- **Debug**: `GET /tray` now also returns `title`, `panelVisible`, and `checked` on the panel entry.

## Verified
- Unit tests: `tray.test.ts` (menu per state, checkbox, title per state, click toggles and persists, Settings switch mirror, Type instead returns to hidden, setup guard), `panel-rules.test.ts` (startup rules, showDock default and migration, state priority), `tests/wake/hotkey.test.ts` (panel combo registers only with a toggle, taken combos tolerated), `design/a11y.test.ts` (reduced-motion covers the ripple selectors, 44 px rule, final-only captions). Typecheck clean, `npx vitest run` 1542 passed (one transient failure on one run did not reproduce on two reruns), `npm run build` ok.
- Real Electron under the lock (`resources/tray/real-check-hidden.mjs`, isolated profile `/tmp/alongside-shell2`, real key, `onboardingDone:true, showDock:false`), 21/21 three times: no panel at start (`panelVisible:false`), dock renderer still renders (`/dock.png` 200), tray title Listening to Live to Speaking to Listening, **a real Live session reaches `live` with the panel hidden**, an injected prompt produces a reply with captions in state and the overlay renders, tray click shows the panel and persists `showDock`, a second click hides it, the session stays live through the toggle, Stop returns to resting, Type instead shows the panel and it hides again when the session ends. A control run with the panel visible (`SHOW=1`) behaves the same (14/14). Results in `docs/shell-shots/real-check-hidden*.json`.
- `backgroundThrottling:false` plus a never-shown window was enough: no 1x1 or off-screen workaround was needed.

## Not verified or not done

- Real light and dark menu bar rendering of the title text; macOS may truncate it on a crowded menu bar. The right-click popup was driven through `activate()`, not a real mouse. The global shortcut was seen registered (accelerator on the menu) but not pressed.
- The confirm toast (NOTIFY) with the panel hidden was not exercised here.
- (b) Escape in inputs was already fixed in `dock/App.tsx` by someone else; no unit test (inline handler). (a) the ripple already honoured `prefers-reduced-motion`; added a test only. (d) clipped focus rings: the dock already uses `outline-offset:-3px`; I did not audit the ~1487 rule further.
- macOS Dock icon click (`activate`) does not show the panel; the menu bar item and Cmd+Alt+P do. The app's Dock icon is not hidden.
- After first-run setup the panel stays visible until the user hides it.
